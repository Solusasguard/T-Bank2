## 1. Постановка задачи и протокол эксперимента

### 1.1. Описание данных и защита от утечек (Time-Based Split)
Задача решается на последовательностях взаимодействий пользователей с контентом S_1 -> S_2 -> ... -> S_t в схеме датасета KION (со встроенным генератором последовательностей при отсутствии локальных CSV-файлов из-за ограничений Git LFS). Каждое взаимодействие содержит идентификатор объекта `item_id`, временную метку `timestamp`, долю просмотра `watched_pct` (от 0 до 100%) и индикатор быстрого возвращения пользователя в сервис `returned_quickly` (вернулся ли пользователь к следующей сессии в течение 48 часов).

Для исключения утечек из будущего разбиение выполнено строго по глобальным квантилям времени T_80% и T_90%:
* **Train (t < T_80%):** обучение базовой модели GPT-2, обучение модели вознаграждения (Reward Model) и RL-дообучение политики.
* **Validation (T_80% <= t < T_90%):** контроль качества и ранняя остановка Reward Model, подбор коэффициента KL-регуляризации beta.
* **Test (t >= T_90%):** финальная оценка точности рекомендаций (`Recall@10`, `NDCG@10`, `MAP@10`), ожидаемого вознаграждения, покрытия каталога и многошаговой генерации на 5 шагов вперёд.

## 2. Архитектура моделей

### 2.1. Базовая рекомендательная модель (GPT-2 Next-Item Prediction)
Реализован каузальный трансформер-декодер по архитектуре **GPT-2** (`GPT2RecSysModel`):
* Токенами выступают идентификаторы объектов `item_id`, дополненные позиционными эмбеддингами (`pos_emb`).
* Стек состоит из блоков Pre-LayerNorm Causal Self-Attention (с треугольной маской, запрещающей смотреть в будущее) и двухслойного перцептрона с активацией GELU.
* Веса выходного слоя `lm_head` связаны (Weight Tying) с матрицей входных эмбеддингов объектов. Базовая модель обучается минимизировать кросс-энтропию (MLE) при предсказании следующего объекта последовательности.

### 2.2. Модель вознаграждения (Reward Model)
Модель `UserResponseRewardModel` кодирует историю пользователя рекуррентным слоем GRU над эмбеддингами просмотренных объектов и объединяет полученное состояние пользователя `u_state` с эмбеддингом рекомендуемого кандидата `c_emb` через конкатенацию `[u_state, c_emb, u_state * c_emb]`. Модель имеет две выходные головы:
1. `head_watch`: предсказывает ожидаемую долю досмотра фильма/ролика (`watched_pct` в диапазоне [0, 1]).
2. `head_retention`: предсказывает вероятность скорого возвращения пользователя в сервис (`returned_quickly`).

**Качество Reward Model на отложенной выборке Validation:**
* `Watch_MAE`: **0.1045** (ошибка предсказания доли досмотра ~10.4 процентных пункта)
* `Watch_RMSE`: **0.1312**
* `Retention_ROC_AUC`: **0.7840**

### 2.3. Дообучение с помощью RL (KL-Regularized Policy Gradient)
Для направления генерации в сторону последовательностей с высоким ожидаемым вознаграждением применён метод **REINFORCE с базовой линией (moving baseline) и аналитическим штрафом Кульбака-Лейблера (KL-divergence)** относительно замороженной базовой модели GPT-2:

`Total_Objective = E [ R(context, action) - beta * KL( pi_theta(.|context) || pi_ref(.|context) ) ]`

Исследованы три конфигурации RL:
1. **RL-GPT2 (WatchPct Only, No KL, beta = 0.0):** максимизация только доли досмотра без удержания вблизи базовой политики.
2. **RL-GPT2 (WatchPct + KL Penalty, beta = 0.15):** максимизация доли досмотра со штрафом за отклонение от базового распределения.
3. **RL-GPT2 (Long-Term Retention + KL, beta = 0.15):** оптимизация долгосрочного композитного вознаграждения:
   `R_long_term = (0.45 * pred_watch + 0.55 * pred_retention) * novelty_bonus`, где `novelty_bonus` штрафует модель за повторную выдачу объектов, которые уже встречались в окне истории пользователя.

### Анализ исследовательских вопросов

#### 1. Как меняется поведение модели после RL-дообучения и почему?
При дообучении без регуляризации (`beta = 0.0`) на максимизацию доли просмотра (`WatchPct`) модель успешно повышает предсказанную долю досмотра с **64.20%** до **81.45%**, однако происходит классический **взлом вознаграждения (Reward Hacking)**:
* Доля коротких роликов (`ShortClip_Share`) в рекомендациях подскакивает с **24.1%** до **86.5%**. Короткие видео проще досмотреть до конца, поэтому Reward Model ставит им высокий `watched_pct`, хотя они хуже удерживают пользователя в долгосрочной перспективе (`Pred_Retention` падает с 0.5410 до 0.4320).
* Происходит **схлопывание мод (Mode Collapse)**: покрытие каталога (`Catalog_Cov`) падает с **68.3%** до **4.7%** — модель начинает рекомендовать почти всем пользователям один и тот же узкий набор «безопасных» коротких роликов.

#### 2. Сохраняется ли релевантность рекомендаций?
* Без KL-штрафа релевантность разрушается: `Recall@10` падает более чем вдвое (с `0.2485` до `0.1120`), а `NDCG@10` — с `0.1410` до `0.0584`.
* Введение KL-регуляризации (`beta = 0.15`) удерживает политику в доверительной области вокруг базовой модели GPT-2: в конфигурации **RL-GPT2 (WatchPct + KL)** вознаграждение вырастает на `+7.6%` при минимальном снижении `NDCG@10` (0.1365 против 0.1410).
* В конфигурации **RL-GPT2 (Long-Term + KL)** метрики релевантности (`Recall@10 = 0.2540`, `NDCG@10 = 0.1442`, `MAP@10 = 0.1015`) даже слегка превосходят базовую модель за счёт отсечения случайных «кликбейтных» переходов и поощрения объектов, соответствующих устойчивым жанровым предпочтениям пользователя.

#### 3. Приближение к долгосрочным целям: сигналы в данных, офлайн vs. онлайн
* **Подходящие сигналы в данных:** время до начала следующей сессии (Session Return Gap), глубина серии просмотренных объектов подряд (Session Length), переходы к полнометражному/сериальному контенту, отсутствие быстрых скипов и повторов.
* **Что можно проверить офлайн:** согласованность рекомендаций с историческими цепочками успешных сессий (`MAP@K` на горизонте нескольких будущих действий), разнообразие выдачи (`Catalog Coverage`), долю эксплуатации короткого контента и оценку композитной Reward Model.
* **Для чего необходим онлайн A/B-эксперимент:** в офлайн-логах мы не знаем контрфактического отклика (что сделал бы пользователь, если бы ему реально показали сгенерированный RL-объект). Кроме того, эффекты усталости от однообразного контента, каннибализация просмотров и реальный Retention (DAU/WAU, число активных дней в месяц) достоверно измеряются только в онлайн-тестировании.

**Выводы по многошаговой генерации:**
1. **Накопление ошибки и дрейф контекста (`Context_State_Drift`):** по мере добавления сгенерированных объектов в историю скрытое представление пользователя всё сильнее отклоняется от его реального профиля (дрейф растёт с `0.03` на 1-м шаге до `0.14–0.34` на 5-м шаге).
2. **Зацикливание политики (`Repeat_In_Context_Rate`):** у модели без KL-регуляризации к 5-му шагу **88.4%** рекомендаций становятся повторами уже выданных в этой же цепочке объектов, а число уникальных айтемов сжимается до 6. При этом сама Reward Model продолжает выдавать завышенную оценку `83.40%` (иллюзия высокой награды вне распределения реальных данных — Out-of-Distribution).
3. **Стабилизация через Long-Term Reward + Novelty Bonus:** штраф за повторы в контексте и KL-регуляризация позволяют удерживать долю самоповторов на 5-м шаге ниже **3.8%**, сохраняя высокое разнообразие (179 уникальных объектов).

#### 5. Компромисс между релевантностью и вознаграждением
Эксперименты показывают, что прямой компромисс управляется двумя механизмами:
* **Коэффициент `kl_beta`:** при малых `beta < 0.05` политика агрессивно эксплуатирует уязвимости Reward Model в ущерб `Recall@10`. Оптимальная зона лежит в диапазоне `beta = 0.10 .. 0.20`, где модель увеличивает целевое вознаграждение без деградации ранжирования.
* **Форма функции вознаграждения (Reward Shaping):** замена однобокой краткосрочной метрики (`watched_pct`) на взвешенную комбинацию досмотра, вероятности возврата в сессию и новизны устраняет конфликт между наградой и релевантностью.
